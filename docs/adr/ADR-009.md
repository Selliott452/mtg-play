# ADR-009: Card definitions ride inside GameState

## Status

Accepted (P2.1 review, 2026-07-20)

## Context

ADR-004 makes the engine a pure resumable function of `GameState`: pending decision requests
are re-derived from state alone (`pendingRequestOf`), and stack entries must carry what a
spell *does*. The card-definition contract therefore has to be reachable from state types —
and `mtg-core` is the only module state types may name. P2.1's original spec placed the SPI
in `mtg-rules`; implementation showed that placement is incompatible with the stateless
model, and the packet delivered it as `dev.mtgplay.core.definition` with definitions supplied
through `MatchConfig.definitions` and stored in `GameState`.

## Decision

**Card definitions are part of `GameState`.** The contract (`CardDefinition`,
`SpellDefinition`, `TimingClass`, `TargetSpec`, `ManaAbility`, `ResolutionEffect`,
`ResolutionContext`) lives in `mtg-core` as nouns plus pure-function values; implementations
live in `mtg-cards` (and test fixtures). A `CardRef` without a definition is an inert,
uncastable card. `mtg-core`'s charter is refined accordingly: *no game-rule decisions* —
definition values are data the rules engine interprets, not engine logic.

Two related surface rulings:
- `pendingRequestOf(state)` is formally part of the ADR-004 engine surface — the pure
  derivation of the pending request, available to any driver resuming a stored state.
- Standalone mana-ability activation at priority (CR 605.3a) is deliberately not enumerated
  until a card can profitably float mana outside payment (Phase 5 horizon); payment plans
  subsume all earlier uses. Revisit when the first such card lands.

## Consequences

- State is fully self-contained: serialize a `GameState`, resume anywhere — the Phase 7
  protocol and ADR-007 filtering build on this directly.
- **State identity excludes definition identity.** `ResolutionEffect` values have reference
  equality only; the replay fingerprint intentionally omits definitions. Replay correctness
  therefore requires the same `MatchConfig` (same definitions), which ADR-006 already demands.
- **Rules out:** an engine-owned definition registry; definition lookup through anything but
  state; definition implementations (card behavior) inside `mtg-core` or `mtg-rules`.
