# ADR-007: Per-seat state filtering is an engine responsibility

## Status

Accepted

## Context

Players may not see everything: opponents' hands, face-down cards, library order, and the
contents of some hidden zones are private. An AI agent occupying a seat must be given exactly
the information a player in that seat could legally have — no more (or it can cheat) and no
less (or it cannot play). If filtering were left to each client, one careless or adversarial
driver would leak hidden information.

## Decision

The engine produces a **per-seat filtered view** of the game state: each agent sees exactly
what a player in that seat may legally see. Filtering is the **engine's responsibility**,
applied at the library boundary — not a courtesy each client is trusted to implement. The
protocol layer (ADR-008) serves these filtered views and never exposes raw full state to a
seat.

## Consequences

- Hidden information cannot leak through a careless or adversarial client; the correctness of
  information hiding is centralized and testable.
- The filter API is the contract the protocol's per-seat state messages are built on (P7.1).
- The engine must model visibility explicitly — who may see each zone and characteristic —
  which is designed in alongside zones and `GameState` (ADR-002).
- **Rules out:** handing an agent or client the unfiltered `GameState` and trusting it to hide
  information; client-side redaction as the security boundary; leaking library order,
  opponents' hands, or face-down card identities into a seat's view.
