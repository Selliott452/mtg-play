# ADR-006: Determinism via a match-owned seeded PRNG; replay = config + decisions

## Status

Accepted

## Context

Reproducibility is foundational for an AI-training engine: debugging, regression tests, and
learning all depend on replaying a game exactly. Two things introduce non-determinism —
randomness (shuffles, coin flips, random effects) and player choices — and both must be
captured completely.

## Decision

All randomness draws from a single **match-owned seeded PRNG**. The seed is part of
`MatchConfig`; shuffles, coin flips, and any future random effect draw from the match PRNG
only. The PRNG is `dev.mtgplay.core.random.Rng`: an **in-repo pure splitmix64**, not a
wrapper over a platform RNG — platform RNGs don't guarantee algorithm stability across
versions, and replay corpora must stay valid forever, so the algorithm (including `nextInt`'s
rejection sampling) is a frozen contract pinned by known-answer tests against the published
vectors. **Direct use of `kotlin.random.Random` or `java.util.Random` anywhere in the `mtg-*`
modules is a review-blocking defect**, enforced mechanically by a detekt `ForbiddenImport`
rule (see CONVENTIONS.md) with no sanctioned exceptions and no suppressions.

A **replay is `(MatchConfig, List<Decision>)`**: the seed plus the ordered decisions fully
reconstruct any game. An acceptance test replays a recorded game and asserts the final state
hash matches (PLAN.md §2.2). Every transition also appends typed `GameEvent`s to a log, but
that log is **derived observability** — for replay display and debugging — and is **never
load-bearing** for rules logic.

## Consequences

- Any game is reproducible from a tiny record (seed + selected indices); regression tests and
  learning both rely on it.
- Determinism composes with ADR-004/ADR-005: decisions are indices into engine enumerations,
  so the decision log is compact and unambiguous.
- The seeded-PRNG rule is enforced by lint, not merely by convention; the single exception is
  explicit and greppable.
- **Rules out:** `kotlin.random.Random`/`java.util.Random`, wall-clock or `nanoTime`-style
  entropy, hash- or iteration-order dependence, or any other ambient non-determinism in
  `mtg-*`; treating the event log as an input to rules logic; reconstructing state from events
  rather than from `(config + decisions)`.
