# ADR-004: Decision-point engine — a resumable state machine with typed requests

## Status

Accepted

## Context

Every form of MTG player interaction — mulligans, taking priority, choosing targets, ordering
blockers, resolving optional triggers, choosing payment plans — is the same shape: the engine
reaches a point where a specific player must choose among specific options and cannot proceed
until they do. Injecting player callbacks or interface implementations into resolution code
couples the rules to a particular driver (CLI, network, RL loop), makes the engine
non-resumable, and makes decisions hard to test in isolation. This is the load-bearing design
of the whole project (PLAN.md §2.1).

## Decision

The engine is a **resumable state machine**. It advances autonomously until it needs a
decision, then **suspends and returns a typed request**:

```kotlin
sealed interface AdvanceResult {
    data class NeedsDecision(
        val state: GameState,
        val request: DecisionRequest,   // who decides + enumerated options
    ) : AdvanceResult
    data class GameOver(val state: GameState, val result: MatchResult) : AdvanceResult
}

interface GameEngine {
    fun start(config: MatchConfig): AdvanceResult
    fun advance(state: GameState, decision: Decision): AdvanceResult
}
```

`DecisionRequest` is a sealed hierarchy — `ChooseAction` (a priority window), `ChooseTargets`,
`ChooseBlockerOrder`, `ChooseMulligan`, `ChooseYesNo` (e.g. madness "you may cast"),
`ChoosePaymentPlan`, and so on — each naming the deciding **seat** and carrying enumerated
options with stable indices (ADR-005). A `Decision` is "request id + selected index(es)".
**Every** player interaction flows through `advance`. Resolution code that needs a choice
suspends the advance and surfaces a request; it never calls back into a player.

## Consequences

- One loop serves every driver: CLI, WebSocket protocol (ADR-008), tests, and future RL loops
  are thin drivers of `advance`.
- The engine is trivially pausable and serializable between decisions, which underpins replay
  (ADR-006) and per-seat filtering (ADR-007).
- Options are enumerated by the engine — exactly the substrate that enumerated actions
  (ADR-005) and decision-log replay (ADR-006) build on.
- **Rules out:** player/agent interfaces or callbacks injected into resolution; blocking I/O
  inside the engine; any interaction path that bypasses `DecisionRequest`; hidden decisions a
  driver cannot see.
