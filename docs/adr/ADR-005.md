# ADR-005: Enumerated actions only

## Status

Accepted

## Context

If agents constructed actions freeform — building a "cast Lightning Bolt targeting X" object
and submitting it — the engine would have to validate arbitrary input, legality logic would be
duplicated between "what can I do?" and "is this allowed?", and agents could express illegal or
malformed actions. For an AI-training environment we want a clean, finite action interface and
a single source of legality truth.

## Decision

Agents never construct actions. For each `DecisionRequest` (ADR-004), the engine **enumerates
the legal options**, and the agent selects one by its **stable index**. All legality logic
lives in **one place** — the enumerator — so "what is legal" and "what the engine will accept"
are the same code. Enumeration completeness (every legal action appears; nothing illegal
appears) is a **tested property**, exercised by the fuzz harness (PLAN.md §2.3).

## Consequences

- The agent-facing action space is a finite, indexed list — well suited to RL (sample an
  index), LLM agents (pick from a menu), and scripted tests alike.
- There is no input-validation surface for malformed actions; illegal actions are
  unrepresentable rather than rejected. Restrictions such as hexproof, timing, and payment
  legality are enforced by *exclusion from the enumeration* (e.g. P5.2 hexproof omits illegal
  targets).
- Legality is centralized and testable; enumeration completeness becomes an invariant the
  fuzzer defends (the mitigation for silent wrongness, PLAN.md §7).
- Indices are stable **within a request**, so a recorded `Decision` means the same thing on
  replay (ADR-006); they are not assumed stable across different requests.
- **Rules out:** freeform or constructed actions submitted by agents; duplicated or per-driver
  legality checks; "submit then validate" flows; agents reaching around the enumeration to
  force an action.
